## Hooks

`savedLandmarkEvidence(amenities)` accepts the existing RouteAmenities payload.
`routeLandmarkCandidates(selectedMapFeature, evidence)` returns availability,
routeId, candidates and explanation. It preserves source locations; distance and
fraction are approximate route-proximity display calculations.

`mountRouteLandmarks(openLayersMap, {onStatus, style})` returns `layer`,
`update(selectedMapFeature, evidence)`, `setVisible(boolean)` and `dispose()`.
Default visibility is false. `update(null)` clears stale markers. D mounts it
inside map.js where the existing OpenLayers map is available and forwards these
hooks through their public map wrapper. Keep this layer separate from stop
clusters and replace it when route/pair changes. Inspect marker property
`landmarkCandidate` for original coordinates, source link, source dates and
unknown visibility/familiarity. D owns accessible badge/popup integration.

Call `update(selectedRoute, savedLandmarkEvidence(routeAmenities))` after every
route selection and amenities refresh; call `update(null)` immediately when a
new address calculation begins to clear the previous journey. Pass an explicit
`{availability: 'missing', places: []}` when evidence cannot be supplied instead
of retaining stale points. Failed/unsupported evidence also clears markers.
Use `onStatus` for the limited/missing/empty explanation and wire the toggle to
`setVisible`. Existing stop features retain `sourceFeature` for canonical
provenance; the controller adds no backend/shared-contract field.
